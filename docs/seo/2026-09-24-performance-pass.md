# Performance pass: client JavaScript and Core Web Vitals (2026-09-24)

Site: pay-calculator-australia.com (Next.js 16.1.6 static export in `calc-boiler/`, 894 exported pages).
Follows `docs/seo/2026-09-23-technical-seo-audit.md`. GA4 (gtag) and every Adsterra unit are unchanged:
no monetisation script was removed, delayed or re-ordered.

## Summary

The biggest cost was not the libraries. It was 77 page templates marked `"use client"` that had no state,
effects or event handlers. Each one shipped its whole JSX, plus the data it read, to the browser only to
re-render HTML that was already in the page. Those templates are now server components. The homepage is
split into a server template and one client calculator card, and framer-motion is gone from the app. One
calculator shows how to split a calculator page's long-form content onto the server.

Across all 884 pages present in both builds, mean First Load JS fell from **161.6 to 149.3 KB** gzip. JS fell on
532 pages and rose on one (`/employer-cost-calculator/`, +2.6 KB, which is main's own change). Mean HTML rose from
36.4 to 41.9 KB, because server-rendered content is also serialised into the inline RSC payload. JS and HTML
together fell from **198.0 to 191.2 KB** per page. CLS stayed at 0.000 on all five templates.

Every exported page has the same visible text, `<title>`, meta description, JSON-LD and `<a href>` list before
and after. This was checked by diffing all 885 pages of the pre-merge export and all 894 of the post-merge
export. The one intended difference is on the homepage: 112 nodes (12 sections and the 100-cell "$100" grid)
used to ship at `opacity:0` in the HTML and now render at their final state.

## Method

- **First Load JS.** Next 16 no longer prints per-route First Load JS, so it is computed from the export: the sum
  of every `/_next/static/chunks/*.js` a page's HTML references (`src` and preload `href`), gzip level 9. The
  `noModule` polyfills are excluded, as Next's own figure excluded them. Scripts are in
  `…/scratchpad/measure-js.mjs` and `sitewide.mjs`; they are not committed.
- **Chunk attribution.** No analyzer package was added. `ANALYZE_MAPS=1 npx next build --webpack` now emits
  browser source maps (off by default). Generated bytes were attributed to sources with `source-map-js`, which is
  already in `node_modules`.
- **Lighthouse.** Lighthouse 13.5, mobile preset (simulated throttling), performance only, 2 runs per URL, median.
  Each export was served with `npx serve` (gzip on), baseline on :4001 and new on :4002, with runs interleaved.
  The "after" Lighthouse runs used the build from before `git merge main`. The five measured routes ship
  byte-identical JS in the final build (163.4 / 159.3 / 151.5 / 151.1 / 151.1 KB).
- **Script transfer in Lighthouse** includes gtag and Adsterra: 480 → 423 KB (home), 493 → 429, 540 → 426,
  497 → 425 and 502 → 425 KB.

Page-level findings:

- **framer-motion:** 129 KB raw (`1002-*`) on the homepage only. `modules/home/templates/index.tsx` was one
  1,580-line client component using `motion.*`, `AnimatePresence` and `useSpring`. `components/common/section-wrapper.tsx`
  imported framer-motion but nothing used the component. `components/layout/navbar.tsx`, `lib/navigation.ts` and
  `app/site-directory/page.tsx` only mention it in comments.
- **Hook-free client templates:** 77 in total (73 in the first pass, 4 more after the merge). Examples:
  `superannuation-guide.tsx` shipped 61 KB of JSX, `take-home-pay-on-salary.tsx` 22 KB, and `tax-on-salary.tsx`,
  every state page, the tax tables, and all award and guide templates did the same.
- **Constants in client bundles:** `lib/constants/modern-awards.ts` (63 KB) went to the browser because
  `modules/guide/award-page-parts.tsx` was client-only for `PrintButton`'s `window.print()`.
  `lib/authors.ts` (17 KB) went through `author-box.tsx` from client guides. After G4 was merged, the public-holiday
  dataset reached the browser through `overtime-penalty-rates-guide.tsx`. `lib/constants/australian-tax.ts` (10 KB)
  is legitimately client, because the calculators run on it.
- **lucide-react** is already imported per icon: the source maps show one module per icon (`src/icons/*.ts`), since
  lucide-react is on Next's default `optimizePackageImports` list. **radix** is tree-shaken to the Accordion family
  (17 KB). Neither was a problem.
- **JSON-LD** is serialised a second time into the RSC payload (4 blocks, about 3 KB on `/take-home-pay-on/80000/`).
  Any element rendered through React ends up there, and the amount is under 2% of the payload. Not worth a hack.
- **Inline RSC payload** was 137–148 KB raw per page at baseline. Most of it is the server-rendered mega menu and
  footer (see the 2026-09-23 audit). The nav already uses short `.sn-*` classes, so there is little left to trim
  without changing `next/link` to plain `<a>`, which would change client-side navigation.
- **Fonts** are already self-hosted, subset to latin plus latin-ext with `unicode-range`, use `font-display: swap`,
  and preload only the two above-the-fold faces (DM Sans normal, Bricolage normal). No change.

## Changes (one commit each)

1. **`perf: render 73 static page templates as server components`.** Removed `"use client"` from 73
   modules in `modules/{guide,programmatic,state,tax-tables,calculator}` that have no hooks or handlers.
   `PrintButton` moved to `modules/guide/print-button.tsx` (client). `award-page-parts.tsx` re-exports it and is now
   server-only, so the award rate data stays on the server. `centrelink-crisis-payment` and
   `cost-of-living-payment-2026` were left as client: they call a helper exported from a client module.
2. **`perf(home): server-render the homepage and drop framer-motion`.**
   - `modules/home/templates/index.tsx` is now a server component: hero, 12 sections and the FAQ.
   - `home-calculator.tsx` is the only client part. The donut uses the existing `.donut-segment` CSS transition,
     the $100 grid a CSS keyframe (`.dollar-cell` in `globals.css`), the collapsible panels tw-animate utilities,
     and the headline figure a ~20-line `requestAnimationFrame` tween that honours reduced motion.
   - The static HTML now shows the donut filled. Before, it was drawn at `0 502` until hydration.
   - `HEAD_TERM_PRIMARY` moved to `modules/calculator/head-term-primary.ts`, so server code can read it.
   - `SectionWrapper` lost framer-motion (CSS fade-up). No app code imports framer-motion any more.
3. **`perf(income-tax-calculator): server-render the content below the calculator`.** The client module renders the
   hero and calculator card and takes `children`. `income-tax-calculator-content.tsx` (server) holds the tables,
   worked examples, FAQ and sources. This is the pattern for every other calculator page.
4. **`build: explicit optimizePackageImports and an opt-in source-map build`.** Sets `optimizePackageImports:
   ["lucide-react", "radix-ui"]` and adds `productionBrowserSourceMaps` behind `ANALYZE_MAPS=1`. Neither changes the
   bundles today.
5. **Merge of main.** Main's two MLS link fixes were re-applied in `income-tax-calculator-content.tsx`.
6. **`fix(perf): stop 53 static routes downloading the homepage calculator chunk`.**
   - Found by the site-wide check. Once the homepage server template rendered `next/link` directly, the static
     export resolved Link's chunk list for about 50 static routes (most calculators, `/news/`, the 404) from the
     root page entry.
   - Those routes then downloaded the homepage calculator chunk (35 KB raw).
   - The homepage now renders Link through `modules/home/templates/home-link.tsx`, a one-line client re-export.
     It is the same component with the same client navigation.
   - Re-check after any change: `grep -l 'app/page-' out/**/index.html` should list only `out/index.html`.
7. **`perf: render 4 more static guides as server components`.** fringe-benefits-tax, overtime-penalty-rates-guide,
   salary-packaging-guide and healthcare-worker-pay. The first scan's regex matched "pro*motion*" in their prose.

## Trade-off to know about

Moving content from client to server components takes JS off the page, but the RSC payload inlined in the HTML
grows by about the same markup. Lighthouse's simulated FCP rose from 1.21 to 1.36 s on the three content-heavy
templates (home, award, guide), because Lantern charges the larger document before first paint. LCP, the metric
that ranks, held or improved on every template, and TBT fell on the homepage. Real phones pay parse, execute
and hydrate costs for JS that they do not pay for inert HTML, so field INP and LCP should move more than the lab
numbers show. Check CrUX or PageSpeed field data 28 days after deploy.

## Remaining items (not done here)

1. **"What to check next" data on every page (≈10 KB gzip).** `lib/related-links.ts` rides in the layout chunk
   because `WhatsNext` needs `usePathname()` and the root layout can't know the path on the server. The fix is to
   render `WhatsNext` from each route's server tree, for example a shared page shell or a per-template slot, and
   pass it the path. That touches ~180 page files, so it was left out of this pass.
2. **Other calculators.** About 80 calculator modules are still one client component that includes their
   long-form content. Apply the `children` split from commit 3. The candidates with the most JSX are
   long-service-leave, salary-sacrifice, take-home-pay, HECS and super.
3. **tailwind-merge (8 KB gzip on every page)** comes in through `cn()` in `components/ui/accordion.tsx`. Replacing
   it with plain class joining would change which conflicting classes win in AccordionTrigger overrides, so it
   needs a visual check first.
4. **framer-motion is still in `package.json`** but unused. Run `npm uninstall framer-motion` on main. It was not
   done here because this worktree's `node_modules` is a symlink to the main checkout.
5. **GA `afterInteractive` → `lazyOnload`** is still the owner's call (see the 2026-09-23 audit, item 2).
6. `centrelink-crisis-payment` and `cost-of-living-payment-2026` can go server-side once the `source()` helper and
   class constants in `modules/calculator/centrelink-shared.tsx` move to a non-client file.
